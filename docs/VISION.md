# reel2report 愿景与路线图

## 一句话

把一段软件使用录屏，变成**结构化的步骤序列**（时间戳 + 截图 + 文字描述），再按不同用途渲染成不同的文档。

## 北极星目标

**首要场景：内测反馈。** 把真实的软件使用录屏，变成编码人员或编码 agent 能直接拿来修 bug 的最小信息包。

衡量指标：

> 拿到报告的开发者 / agent，**不看原视频、不追问测试者**，就能复现并定位问题的比例。

三层含义：

1. **压缩**：几十分钟的视频，变成几十个关键步骤，再从中挑出几个问题点。
2. **准确**：步骤、时间戳和截图严格对应，不编造。看不清的地方标成"不确定"，不去猜。
3. **能直接用**：输出格式让 agent 拿到就能动手，比如复现步骤、预期 / 实际结果、相关截图、严重程度。

## 核心架构：一个引擎，多种输出

```
录屏 ──► [步骤提取引擎] ──► 结构化步骤序列 (steps.json + 截图)
                                     │
            ┌────────────────┬───────┴────────┬──────────────────┐
            ▼                ▼                ▼                  ▼
       内测反馈报告       教程博客       小红书图文教程        其他渲染器 …
       (首要场景)
```

- **步骤提取引擎**：在本地抽帧、去重、对齐时间戳，再用多模态模型理解每一步。各种用途共用这一部分。
- **渲染器**：同一份步骤序列，按目标场景生成不同风格的文档。新增一个用途就是新增一个渲染器，引擎不用改。

## 设计原则

- **能本地算的不交给模型**：抽帧、去重、对齐都用 ffmpeg 等工具在本地完成，只把筛过的少量关键帧发给模型。
- **模型可替换**：默认使用 **DeepSeek 原生多模态模型**负责看图和撰写文档，通过统一接口接入，以后换成其他模型或本地模型不用改主流程。
- **中间结果都可查**：每一步都把结果落到磁盘（帧、JSON），出问题能复查，也能只重跑其中一步。
- **报告分两层**（内测场景）：一份给人看（Markdown 加图），一份给 agent（结构化 JSON 或精简 Markdown，只带有问题的截图），控制 token 成本。

### 不做的事

- 通用视频摘要（影视、会议等非软件操作类视频）
- 自动化测试的录制与回放
- 埋点 / 数据统计分析平台

## 路线图

### 近期（v0.x）：跑通内测反馈闭环

1. **核心命令行流程**：`reel2report rec.mp4`，完成 mp4 → 关键帧 → DeepSeek 看图 → Markdown 报告 + 截图目录。
2. **语音解说**：把测试者的口述转写成带时间戳的文字，和画面对齐后一起交给模型。
3. **触摸点识别**：配合系统的"显示触摸"选项，在截图上标出点击位置，提高动作判断的准确度。
4. **产品上下文**：在配置文件里写页面列表、功能说明和预期行为，模型据此判断哪里"不符合预期"。

### 中期：好用、好接入

5. **提交入口**：网页上传、Telegram / 飞书机器人、监听网盘文件夹，方便内测用户在手机上提交。
6. **输出对接**：自动创建 GitHub Issue、写入 Notion，同一个问题被多人报告时自动合并。
7. **MCP Server**：编码 agent 可以直接调用，比如"查一下这个 bug 的步骤截图"。

### 内容创作方向：录屏 → 教程

步骤提取引擎本身与用途无关，所以同一套流程也能用来自动化制作教程内容：

8. **教程博客渲染器**：把操作录屏生成图文并茂的分步教程，可输出 Markdown / HTML，适合发到博客、文档站、知乎、公众号等平台。
9. **小红书图文渲染器**：
   - 挑出最关键的几步，生成竖版拼图或卡片（含步骤编号、高亮框、简短说明）
   - 按小红书风格生成标题、正文和话题标签
   - 控制图片数量和尺寸，符合平台规范
10. **横屏画面摆正**：横屏应用在竖屏录屏里是侧着的。需要可靠地判断“是否旋转、往哪个方向转”（让模型直接判断时，方向错了一半，转出来是倒的）。
11. **截图美化**：自动裁剪、打码隐私信息（手机号、头像等）、加高亮框和箭头标注。
12. **风格模板**：用户可以自定义语气（专业 / 口语化 / 种草风）、品牌色和水印。

### 远期：从单份报告到全局洞察

13. **多报告聚合**：同一版本的所有内测报告汇总成问题排行。
14. **版本对比**：同一操作路径在新旧版本里的表现差异，用来做回归检查。
15. **结合日志 / 埋点**：把录屏时间轴和应用日志对齐，定位更准。
16. **教程保鲜**：软件改版后，用新录屏对比旧教程，提示哪些步骤已经过期。

## 待确认事项

- DeepSeek 当前多模态 API 的模型名称、单次请求的图片数量上限、图片尺寸要求和价格，开发前查清后再确定分批和压缩策略。
- 语音转写方案（本地 Whisper，或者云端 API）。
- 各内容平台（小红书等）的图片规格和发布规范。
